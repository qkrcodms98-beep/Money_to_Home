# 개발 환경 맞추기 (처음 하는 사람용)

| 항목 | 내용 |
| --- | --- |
| 대상 | 프로젝트를 처음 해 보는 팀원 |
| 걸리는 시간 | 40분 ~ 1시간 |
| 목표 | 네 명의 PC에 같은 폴더, 같은 프로그램, 같은 DB가 있는 상태 |
| 막히면 | 화면을 캡처해서 팀장에게 보낸다. 혼자 오래 붙잡지 않는다. |

**순서대로 따라 한다. 건너뛰지 않는다.** 각 단계 끝에 "확인"이 있다. 확인이 안 되면 다음으로 넘어가지 않는다.

## 전체 순서

1. 폴더 만들기
2. 프로그램 네 개 설치 (Git, Python, MariaDB, VS Code)
3. 프로젝트 내려받기
4. DB 만들기
5. `.env` 파일 만들기
6. 마지막 확인

---

## 0. 먼저 알아 둘 말

| 말 | 뜻 |
| --- | --- |
| 폴더, 경로 | 폴더는 파일을 담는 곳이고, 경로는 그 폴더의 주소다. 예: `C:\projects\Money_to_Home` |
| 터미널 | 글자로 명령을 내리는 창. 이 문서에서는 VS Code 안의 터미널을 쓴다. |
| 명령 | 터미널에 한 줄 적고 Enter를 누르는 것 |
| 저장소 | 프로젝트 파일이 모여 있는 곳. GitHub에 있는 것을 내 PC로 내려받는다. |
| 브랜치 | 저장소의 작업 갈래. 지금은 `docs/project-overview`를 쓴다. |
| DB | 자료를 표로 보관하는 프로그램. MariaDB를 쓴다. |

## 1. 폴더 만들기

네 명이 **똑같은 경로**를 쓴다. 경로가 같아야 서로 화면을 보며 도울 수 있다.

1. 파일 탐색기를 연다 (키보드의 `Windows` + `E`).
2. 왼쪽에서 **내 PC**를 누르고 **로컬 디스크 (C:)** 를 연다.
3. 빈 곳을 오른쪽 버튼으로 누르고 **새로 만들기 > 폴더**를 고른다.
4. 이름을 `projects`로 적는다.

지켜야 할 것

- 폴더 이름에 **한글과 띄어쓰기를 쓰지 않는다.** 일부 프로그램이 한글 경로에서 오류를 낸다.
- 바탕화면, 문서, OneDrive 안에 만들지 않는다. 자동으로 올라가는 폴더라 파일이 꼬일 수 있다.

**확인**: 탐색기의 주소 칸에 `C:\projects`가 보인다.

---

## 2. 프로그램 설치

네 개를 순서대로 설치한다. 설치 화면에서 따로 적지 않은 것은 고치지 않고 **다음(Next)** 을 누른다.

### 2.1 Git

파일의 변경 기록을 남기고 팀과 주고받는 프로그램이다.

1. https://git-scm.com/downloads 에서 Windows용을 내려받아 실행한다.
2. 끝까지 **Next**를 누르고 **Install**을 누른다.

### 2.2 Python 3.12

1. https://www.python.org/downloads/ 에서 **3.12**로 시작하는 버전을 내려받아 실행한다. 맨 위의 최신 버전이 3.12가 아니면 아래 목록에서 3.12를 찾는다.
2. **첫 화면 아래쪽의 "Add python.exe to PATH"를 반드시 체크한다.** 이것을 빼먹으면 터미널이 Python을 찾지 못한다.
3. **Install Now**를 누른다.

### 2.3 MariaDB 11.4

1. https://mariadb.org/download/ 에서 버전을 **11.4**로 고르고 Windows용 MSI 파일을 내려받아 실행한다.
2. 설치 중에 **root 비밀번호**를 묻는다. 정한 비밀번호를 **메모장에 적어 둔다.** 잊으면 다시 설치해야 한다.
3. "Use UTF8 as default server's character set"이 보이면 체크한다.
4. HeidiSQL을 함께 설치할지 묻는 항목은 그대로 둔다 (함께 설치된다).
5. 나머지는 **Next**를 누른다.

### 2.4 VS Code

코드를 보고 고치는 편집기다.

1. https://code.visualstudio.com/ 에서 내려받아 실행한다.
2. 끝까지 **다음**을 누른다.

### 설치 확인

1. VS Code를 연다.
2. 위쪽 메뉴에서 **터미널 > 새 터미널**을 누른다. 아래에 글자를 적는 창이 열린다.
3. 아래 두 줄을 한 줄씩 적고 Enter를 누른다.

```
git --version
```

```
python --version
```

**확인**: `git version 2.어쩌고`와 `Python 3.12.어쩌고`가 나온다. "찾을 수 없습니다"가 나오면 VS Code를 껐다 켠 뒤 다시 해 본다. 그래도 안 되면 그 프로그램을 다시 설치한다 (Python은 2.2의 2번을 꼭 확인).

## 3. 프로젝트 내려받기

1. VS Code의 터미널에 아래를 한 줄씩 적는다.

```
cd C:\projects
```

```
git clone https://github.com/semiproejct/Money_to_Home.git
```

```
cd Money_to_Home
```

```
git checkout docs/project-overview
```

2. 처음이면 GitHub 로그인 창이 뜬다. 자기 GitHub 계정으로 로그인한다. "권한이 없다"고 나오면 팀장에게 저장소 초대를 부탁한다.
3. VS Code 메뉴에서 **파일 > 폴더 열기**를 누르고 `C:\projects\Money_to_Home`을 고른다.

마지막 명령의 브랜치 이름은 문서가 `develop`에 합쳐지면 `develop`으로 바뀐다. 팀장이 알려 준다.

**확인**: VS Code 왼쪽에 아래 폴더와 파일이 보인다.

```
Money_to_Home
├─ db
│  └─ schema.sql
├─ docs
├─ .env.example
├─ .gitignore
└─ README.md
```

## 4. DB 만들기

1. 시작 메뉴에서 **HeidiSQL**을 찾아 연다.
2. 왼쪽 아래의 **신규**를 누른다.
3. 오른쪽에 아래처럼 적는다.

| 칸 | 값 |
| --- | --- |
| 호스트명 / IP | `127.0.0.1` |
| 사용자 | `root` |
| 암호 | 2.3에서 정한 비밀번호 |
| 포트 | `3306` |

4. **열기**를 누른다. 저장할지 물으면 **예**를 누른다.
5. 위쪽 메뉴에서 **파일 > SQL 파일 불러오기**를 누르고 `C:\projects\Money_to_Home\db\schema.sql`을 고른다.
6. 키보드의 **F9**를 누른다. 실행하는 단추다.
7. 왼쪽 목록을 오른쪽 버튼으로 누르고 **새로 고침**을 누른다.

**확인**: 왼쪽에 `money_to_home`이 생기고, 펼치면 표 8개가 보인다.

```
apartment_prices, apartments, data_collections, loan_products,
profiles, saved_results, trades, users
```

표를 누르면 칸마다 한글 설명이 보인다. 실수로 여러 번 실행해도 괜찮다. 이미 있는 표는 건너뛴다.

## 5. `.env` 파일 만들기

키와 비밀번호를 적어 두는 파일이다. **이 파일은 Git에 올라가지 않는다.** 각자 자기 PC에 만든다.

1. VS Code 왼쪽에서 `.env.example`을 오른쪽 버튼으로 누르고 **복사**를 누른다.
2. 왼쪽 빈 곳을 오른쪽 버튼으로 누르고 **붙여넣기**를 누른다. `.env copy.example` 같은 이름으로 생긴다.
3. 그 파일을 오른쪽 버튼으로 누르고 **이름 바꾸기**를 눌러 `.env`로 고친다. 앞에 점이 있고 뒤에 아무것도 붙지 않는다.
4. `.env`를 열어 `=` 뒤에 값을 적는다. **따옴표와 띄어쓰기 없이** 붙여 적는다.

| 이름 | 적을 값 |
| --- | --- |
| `DATA_GO_KR_KEY` | 팀장이 준 값 |
| `KAKAO_JS_KEY` | 팀장이 준 값 |
| `KAKAO_REST_API_KEY` | 팀장이 준 값 |
| `DB_HOST`, `DB_PORT`, `DB_NAME` | 고치지 않는다. |
| `DB_USER` | `root` |
| `DB_PASSWORD` | 2.3에서 정한 비밀번호 |
| `SESSION_SECRET_KEY` | 비워 둔다. |

5. `Ctrl` + `S`로 저장한다.

절대 하면 안 되는 것

- 키와 비밀번호를 **`.env.example`에 적지 않는다.** 그 파일은 Git에 올라간다.
- 키를 단체방, 캡처, GitHub에 올리지 않는다.

**확인**: 터미널에 아래를 적는다.

```
git status
```

결과에 `.env`가 **보이지 않으면** 맞다. `.env`가 목록에 보이면 팀장에게 알린다.

## 7. 다음에 추가될 단계

프로젝트의 뼈대 코드가 올라오면 아래 두 단계가 더 생긴다. 그때 이 문서를 고쳐서 알린다.

- 라이브러리 설치: `pip install -r requirements.txt`
- 서버 실행: 브라우저에서 `http://localhost:8000`을 열어 화면이 뜨는지 확인

## 자주 막히는 곳

| 증상 | 원인과 해결 |
| --- | --- |
| `python`을 찾을 수 없다고 나온다. | 설치할 때 "Add python.exe to PATH"를 체크하지 않았다. Python을 지우고 다시 설치한다. |
| `git clone`에서 권한 오류가 난다. | 저장소에 초대되지 않았다. 팀장에게 GitHub 아이디를 알려 준다. |
| HeidiSQL이 접속되지 않는다. | 비밀번호가 틀렸거나 MariaDB가 꺼져 있다. PC를 다시 켠 뒤 해 본다. |
| 3306 포트를 쓸 수 없다고 나온다. | 다른 DB(MySQL 등)가 이미 깔려 있다. 팀장에게 알린다. |
| `.env`의 이름이 `.env.txt`가 된다. | 메모장으로 만들면 그렇게 된다. VS Code에서 만든다. |
| 터미널의 경로가 다르다. | `cd C:\projects\Money_to_Home`을 다시 적는다. |

## 하지 말아야 할 것

- 폴더 이름과 파일 이름을 바꾸지 않는다. 다른 사람의 코드가 그 이름을 쓴다.
- 표를 HeidiSQL에서 손으로 만들거나 고치지 않는다. `db/schema.sql`로만 만든다.
- `main`과 `develop` 브랜치에 직접 올리지 않는다.
- 모르는 명령을 인터넷에서 찾아 그대로 실행하지 않는다. 먼저 팀장에게 묻는다.
